# Security Policy

## Reporting a Vulnerability

Security vulnerabilities should be reported privately rather than publicly disclosed.

Please do not publish details about an unpatched vulnerability in a public issue.

When reporting a vulnerability, include:

- A description of the issue
- Steps to reproduce it
- The potential impact
- Any suggested fixes, if available

## Supported Versions

Currently, the project is in early development.
Security support policies and supported versions will be established as the software develops.

## Security Priorities

Security is an important part of this project. Development should prioritize:

- Protection of personal information.
- Secure authentication and authorization
- Protection against unauthorized access
- Reliable data storage and handling
- Regular security reviews and testing
